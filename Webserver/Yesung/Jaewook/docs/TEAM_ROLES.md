# 팀원 역할 분담

## 프로젝트 팀 구성

본 프로젝트는 SLAM과 센서 퓨전, Navigation, ROS 2 시스템 제어, 관리자용 Qt UI, 사용자용 Web UI의 다섯 영역으로 나누어 개발한다.

각 담당자는 자신의 기능을 독립적으로 개발하면서 공통 토픽, 서비스, 액션 및 메시지 규격을 기준으로 시스템을 통합한다.

---

## 1. 팀원 A — SLAM & Sensor Fusion 엔지니어

> 내 위치는 어디이고, 주변 지도는 어떻게 생겼는가?

### 담당 업무

- 엔코더, LiDAR, IMU 센서 데이터 취합
- 엔코더 데이터를 이용한 Odometry 추출
- EKF 기반 센서 퓨전과 측정 노이즈 보정
- Gmapping, Cartographer 또는 SLAM Toolbox를 이용한 2D Grid Map 생성
- 생성된 지도 파일 저장 및 관리
- 저장된 지도와 센서 데이터를 이용한 위치 추정 지원

### 주요 협업

- 하드웨어 조립 직후 STM32 담당 파트와 센서 데이터 및 엔코더 값을 우선 검증한다.
- 팀원 B에게 지도, 위치 추정 결과, TF 및 센서 토픽을 제공한다.
- 팀원 C와 센서 오류 및 위치 추정 실패 상태의 처리 기준을 협의한다.

---

## 2. 팀원 B — Navigation & Simulation 엔지니어

> 부품이 없어도 개발할 수 있는 환경을 만들고, 목적지까지 길을 찾는다.

### 담당 업무

- Gazebo 기반 가상 환경과 가상 로봇 시뮬레이션 구축
- 실제 로봇 구조를 반영한 URDF 및 센서 모델 설정
- 부품 도착 전 팀 전체가 사용할 수 있는 테스트 환경 제공
- Nav2 서버 구성
- 글로벌·로컬 경로 계획 설정
- Costmap 및 장애물 회피 파라미터 튜닝
- 목적지 이동, 경로 재탐색 및 자동 순찰 기능 검증

### 주요 협업

- 시뮬레이터를 우선 구축하여 다른 팀원의 병렬 개발을 지원한다.
- 팀원 A의 지도, TF, Odometry 및 위치 추정 결과를 Nav2와 연결한다.
- 팀원 C의 상태 제어 로직과 Nav2 Action·Service 인터페이스를 맞춘다.

---

## 3. 팀원 C — ROS Architecture & 시스템 제어

> 로봇의 전체 뼈대를 잡고, 뇌인 행동 로직 역할을 수행한다.

### 담당 업무

- 전체 ROS 2 패키지 및 파일 구조 설계
- 노드, Topic, Service, Action 및 Message 인터페이스 정의
- Tailscale VPN 환경의 ROS 2 DDS 통신 검증
- 멀티캐스트·유니캐스트 제약과 원격 브리지 환경 설정
- 센서, UI 및 Navigation 명령을 취합하는 중앙 제어 로직 구현
- State Machine 또는 Behavior Tree 기반 행동 상태 관리
- 충돌, 저전력, 통신 오류 및 긴급 정지 처리

### 주요 협업

- 모든 팀원이 사용할 공통 인터페이스와 메시지 규격을 먼저 확정한다.
- 팀원 A·B의 로봇 상태와 주행 결과를 팀원 D·E가 사용할 수 있는 형태로 제공한다.
- 긴급 정지 명령이 다른 모든 행동보다 우선하도록 시스템 정책을 관리한다.

---

## 4. 팀원 D — 관리자 UI(Qt) 엔지니어

> 관리자가 로봇의 상태를 통제하고 모니터링한다.

### 담당 업무

- C++·Qt 기반 관리자용 데스크톱 관제 프로그램 개발
- 자율·수동 제어 전환 기능
- 순찰 시작, 일시정지, 재개 및 종료 기능
- 셧다운 및 긴급 정지 버튼 구현
- 현재 속도, 주행 상태, 배터리 및 오류 정보 표시
- 카메라 이미지 Topic 구독과 실시간 영상 스트리밍
- RViz 플러그인 또는 Map Topic을 이용한 현재 위치 시각화
- 지도 기반 미니맵과 이동 방향 표시

### 주요 협업

- 팀원 C가 정의한 제어 명령과 상태 Topic·Service를 사용한다.
- 팀원 E와 관리자·사용자 화면에 공통으로 필요한 데이터 형식을 협의한다.
- 긴급 정지와 원격 제어 명령의 응답 시간을 함께 검증한다.

---

## 5. 팀원 E — 사용자 Web UI & Data Bridge 엔지니어

> 사용자 명령을 ROS로 전달하고, UI에 필요한 데이터를 제공한다.

### 담당 업무

- 모바일·태블릿에서 접근 가능한 웹 기반 사용자 화면 개발
- 출발지·목적지 선택 기능
- 안내 출발, 일시정지 및 취소 기능
- `rosbridge_suite` 또는 WebSocket 기반 ROS-Web 연결 구성
- 웹 명령을 ROS 2 메시지로 변환하여 팀원 C의 시스템 제어 노드에 전달
- ROS 2 상태 정보를 Web과 Qt 화면에 필요한 데이터로 정제
- 원격 접속 및 Tailscale 네트워크 환경에서 통신 검증

### 주요 협업

- 팀원 C와 사용자 명령 및 로봇 상태 메시지 규격을 정의한다.
- 팀원 D와 공통 상태 데이터, 오류 메시지 및 지도 위치 표현 방식을 맞춘다.
- 웹 연결이 끊어진 경우 로봇이 안전한 상태를 유지하도록 예외 처리 기준을 공유한다.

---

## 협업 구조

| 제공자 | 제공 정보 | 주요 사용 팀원 |
|:---|:---|:---|
| 팀원 A | `/scan`, `/imu`, `/odom`, TF, 지도, 위치 추정 결과 | 팀원 B, C, D |
| 팀원 B | 경로, 주행 상태, Nav2 Action, 속도 명령 | 팀원 C, D, E |
| 팀원 C | 시스템 상태, 행동 명령, 안전 제어 인터페이스 | 전체 팀 |
| 팀원 D | 관리자 제어 명령, 관제 요구 데이터 | 팀원 C, E |
| 팀원 E | 사용자 안내 명령, WebSocket 데이터 | 팀원 C, D |

## 권장 통합 순서

1. 팀원 C가 공통 ROS 2 인터페이스와 패키지 구조를 정의한다.
2. 팀원 B가 Gazebo와 가상 로봇을 구축하여 테스트 환경을 제공한다.
3. 팀원 A가 가상 센서로 SLAM·센서 퓨전을 먼저 검증한 뒤 실제 센서와 연결한다.
4. 팀원 B가 지도와 위치 추정 결과를 Nav2에 연결한다.
5. 팀원 C가 주행·안내·순찰·오류 상태를 행동 로직에 통합한다.
6. 팀원 D와 E가 Qt·Web UI를 공통 제어 인터페이스에 연결한다.
7. 전체 팀이 Tailscale 환경에서 통합 테스트와 안전 기능을 검증한다.
